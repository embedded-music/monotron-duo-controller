# Project plan

## Goal

Build a demonstrable, repeatable way to play and sequence a Korg monotron DUO
from a Cardputer-ADV, then accept notes from BLE MIDI and USB MIDI controllers.
Pitch is generated by an MCP4725 DAC and note state by a protected gate output.

This is a pre-1.0 hardware experiment. Measurements and listening tests take
priority over premature API stability.

## Stage 0 — Characterize the unmodified Monotron

Record the Monotron board revision, photograph both PCB sides, locate the
officially labelled `Vrib`, `Gate`, and `GND` points, and measure their normal
operating ranges while playing the ribbon. Do not inject external voltage yet.

Acceptance criteria:

- Board revision and clear test-point photographs are committed.
- Minimum, maximum, idle, note-on, and note-off voltages are recorded.
- Measurements identify the gate polarity and a safe proposed input range.
- The Monotron still operates normally from its ribbon after measurement.

## Stage 1 — Validate the protected CV/Gate interface

Prototype the MCP4725 pitch output and a buffered or current-limited gate output
on a breadboard. Connect through a removable jack or keyed connector so the
Monotron can still be used independently.

Acceptance criteria:

- A schematic with component values and connector pinout is committed.
- DAC output is verified with a multimeter from zero through the intended range
  before connection to `Vrib`.
- Gate high and low voltages remain inside the measured safe range.
- A manual test can turn a note on/off and sweep pitch without resets, excessive
  heating, or loss of normal ribbon operation after disconnection.

## Stage 2 — Cardputer keyboard proof of concept

Create a minimal PlatformIO/Arduino firmware for Cardputer-ADV. Translate local
key presses into monophonic note events, write pitch through MCP4725 over I2C,
and drive the protected gate output.

Acceptance criteria:

- `pio run` succeeds using the shared workspace PlatformIO cache.
- Serial diagnostics report key, target note, DAC value, and gate state.
- Pressing a mapped key produces a note; releasing the final held key closes
  the gate.
- A ten-minute play test completes without stuck notes or device resets.

## Stage 3 — Calibrated pitch mapping

Measure the actual `Vrib` response rather than assuming a 1 V/octave input.
Store calibration anchors and interpolate a monotonic note-to-DAC table. Add
octave selection, transpose, and pitch bend with output clamping.

Acceptance criteria:

- Calibration can be performed without recompiling firmware.
- Calibration survives reboot.
- Every supported note stays within the Stage 1 safe voltage range.
- Across the chosen playable range, each sustained note is within 15 cents of
  its target after warm-up, or the measured limitation is documented and the
  accepted range is reduced.

## Stage 4 — Performance UI and sequencer

Add an observable Cardputer interface: current note, octave, gate, transport,
tempo, and a compact step sequence. Keep the event path fixed-size and avoid
dynamic allocation during playback.

Acceptance criteria:

- A sequence can be entered, started, stopped, and cleared on the device.
- Tempo remains within 1% over a five-minute measurement.
- UI interaction does not create stuck gates or audible timing stalls.
- An arpeggio using both Monotron oscillators/X-MOD is captured in the devlog.

## Stage 5 — BLE MIDI input

Receive BLE MIDI as a central/client and translate Note On, Note Off, velocity,
and pitch bend into the same internal monophonic event path used by the local
keyboard.

Acceptance criteria:

- The Cardputer reconnects to one documented BLE MIDI controller after reboot.
- Note On/Off and pitch bend work for a continuous ten-minute session.
- Disconnect or radio loss closes the gate within one second.
- Local keyboard operation still works when no BLE controller is connected.

## Stage 6 — USB MIDI host

Add class-compliant USB MIDI host input on ESP32-S3. Treat USB power and host
cabling as a separate hardware problem; do not assume the Cardputer USB-C port
can safely power every controller.

Acceptance criteria:

- The tested controller enumerates by vendor/product ID and endpoint layout.
- Class-compliant Note On/Off and pitch bend reach the common event path.
- Externally powered and bus-powered test arrangements are documented.
- Disconnecting the controller closes the gate and leaves the UI responsive.

## Stage 7 — Demo hardening

Package the breadboard circuit into a mechanically secure adapter, document the
complete build, and record a reproducible demonstration. Optional experiments
may add a second DAC for filter control or map the IMU to musical parameters.

Acceptance criteria:

- All connectors are keyed or unmistakably labelled.
- No exposed conductor can short against the Monotron or Cardputer enclosure.
- A cold-start procedure succeeds three times in succession.
- The repository includes wiring diagrams, calibration data, build/flash steps,
  and a short demo recording or link.

## Explicitly deferred

- Powering the Monotron from the Cardputer.
- Assuming Eurorack-compatible 1 V/octave or gate levels.
- Polyphony; the Monotron DUO remains one gated voice despite having two VCOs.
- Filter CV until pitch and gate are electrically characterized and reliable.
